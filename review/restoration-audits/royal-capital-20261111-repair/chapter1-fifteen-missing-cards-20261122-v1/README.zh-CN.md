15张卡自身的路线标签均为 `IFルート：フェルト`；1029目录还包含其他路线，不能把整话都当作菲鲁特 IF。当前 manifest 的140份已导入正文不含这15张卡。外来抓包 chart 行虽有各自 `branch_num`，`next_scene_list` 均为空；这不能签出无后续，也不能按卡片纵向位置补目标。主表的话级 `1005→1006→1007` 也不是场景级连接。

逐卡的名称、ID、主表原指针、正文／后续未知状态、检索范围和资源证据在 `cards-and-scopes.public-candidate.json`。15卡均有缩略图文件或档案成员索引依据。1007调查另外精确索引了36个本话目录的语音文件，但未试听、未绑定具体场景或节点；其余三组的语音数量没有在引用的封包中核定，不能写成0，更不能把36按五张卡重复相加。

四组检索范围不同，保持各自边界：1029的1843个文件级线索并未全部做结构解析；1005的11个主资料命中和35个保留日志命中完成了对应核查；1006检查了51份旧 Studio 文件、12个只读运行状态及44条录像文件名记录；1007的两次限定 UID 前缀检索均零命中。文件名、采样总览图和资源存在，都不代替完整录像、正文或原生转移。

读取错误单独保留在 `reader-boundaries.public-candidate.json`：

- **1005：已知调查工具错误。** 私有 collector 错把静态四集合投影当作有 `adventure_data` 的原始响应，触发 `KeyError`；已按实际 `content_key`／client manifest 映射修正调查流程，保留原错误和原字节输出。它不是业务 parser 修复。
- **1006：原因未知的原始 JSON 读取失败。** `002609.json` 的完整原始异常文档已由上游保留。传入 `json.loads` 的是 bytes；持有输入的已保存 SHA 是异常后重算，之前的内存 SHA 行没有落盘。异常文档有5个 NUL；后续同输入 SHA 的独立字节快照无 NUL，两者有5字节差异。后续快照不是失败当次 raw capture，独立成功读取不解释或覆盖原失败。本合并没有重跑该失败流程、解码异常文档或改解析器。

`source-field-map.public-candidate.json` 给出逐卡源文件与 JSON pointer、计数的精确派生位置；`input-hashes.public-candidate.json` 绑定本合并所读包文件及当前目录／manifest输入。原调查对更大原始语料的核查时点保持在各自收据中，没有冒称本合并重新重哈全部嵌套语料。输入文件前后 SHA、四组文件清单和公开输出隐私扫描均有记录。

本候选只保留项目相对引用或脱敏外部 reference 和完整哈希，没有复制原玩家账号／session、私人凭据、绝对个人路径、完整异常正文或原命令。没有新识图、浏览器、API、解码、业务 helper 或 Git 操作。下一步需取得各目标自有原始响应，或带身份锚点的完整菲鲁特 IF 录像及连接两端，再由 root 通过正常工作流单独审核；当前不提供占位正文或连接补丁。
