## Request and process lifecycle

The server binds literal loopback and exposes known GET routes only. Static file
containment uses each actual assets/public root and rejects directories and
project-wide traversal. Write methods are rejected. There is no registration,
reload, install, formal-data save or browser-launch endpoint. Local diagnostic
receipts are its only authored outputs.

One synchronous HTTP owner permits only one compiler request at a time. It uses
the absolute ARM Node and verified loader with a45-second communicate timeout,
bounded thread settings and inherited nice19/CPUs0,1. The child has an owned
process group. Timeout or adapter interruption kills and reaps that group before
recording stdout/stderr hashes and a process receipt; no compiler retry occurs.
This is a coherent source lifecycle. Actual process termination/reaping and
timing remain unobserved; post-kill `communicate()` is synchronous rather than a
separately measured hard deadline.

Python inputs pass the copied verifier's bounded same-immutable-input UTF-8
roundtrip checks. JSON parsing is attempted once after admission. A JSON parse
failure retains raw input and exception-document bytes independently with
context/hashes, without normalization, data rewrite or external-operation retry.
JavaScript explicitly round-trips formal source and registry JSON; the historical
packet/source guard body intentionally retains its old parsing behavior. This
review does not claim an explanation or universal cure for the independently
logged decoder mismatch.
