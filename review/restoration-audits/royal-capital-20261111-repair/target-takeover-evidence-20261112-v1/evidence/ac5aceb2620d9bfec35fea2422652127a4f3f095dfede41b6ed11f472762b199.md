## Native mapping and remaining decision

The exported native controller is `AC_felt01_ver2`, sourced from the original
`ac_felt01.prefab`; the recorded prefab SHA matches the current original bytes.
Its motion layer defaults to `act_normal_w` at weight 1; face defaults to
`face_normal_w` at serialized weight 0. Serialized defaults do not establish
runtime weights. The original `StoryMotionCatalog` resolver removes `_w` for
trigger lookup and uses the matching one-shot when that trigger exists.
Therefore a guessed `_w` spelling cannot safely force a held pose.

The controller and 59 exported motion/face/additional clips were inspected as
data. Within the unmodified default motion inventory, sustained closed eyes,
non-smiling lids and low arms make the `punpun` and `nayamu` families useful
diagnostic candidates; the source's small turn/no visible blush favors testing
`punpun` first. This is a curve-supported shortlist, not motion acceptance.
`act_punpun` transitions to `act_punpun_w`, and `face_punpun` independently
transitions to `face_punpun_w`. Corresponding `nayamu` paths also exist. The
whole-body clips contain face curves, so source pixels alone do not prove
whether the original script used a body command, a separate face command or
both. No original CSV, exact onset, runtime layer weights or production entry
comparison is present in this review.

`production-comparison-hypotheses.json` gives precise unaccepted diagnostic
strings using the canonical compiler's comma-separated `body,face,extras…`
format. The first three are `act_punpun`, `act_normal,face_punpun` and
`act_punpun,face_punpun`; the two `nayamu` alternatives preserve the same layer
distinction. The `punpun` held curves have no cheek contribution, head XYZ
`17,18,-5`, body X `-4` and upper arms `0,0`; `nayamu` held curves instead have
cheek `0.5`, head XYZ `-8,-14,-20`, body X/Z `-3,-2` and upper arms `3,1`.
These are native parameter values, not screen coordinates. A full rendered
sequence must establish which projected head, face and shoulder/arm motion
matches. One final-eye-close still cannot distinguish layer ownership.

The current canonical player explicitly clears face state on any nonempty
motion and requests clearing the face layer for a body-only assignment. Its
exact source bytes are bound in the hypothesis file. This is an offline read
of the implementation, not a claim that it was executed in this review. The
predecessor and successor Subaru clothing identities are still outside this
node-5 motion review; never fill them to make a 4→5→6 diagnostic look complete.
